# 质疑回应、投稿前自查与补充分析排序

适用于逐条回应审稿意见、答辩或组会上的质疑、投稿前自查，以及判断哪些补充分析值得做。中英文回应共用同一套判断，英文回应信可用 we，中文正文不用“我们”。

## 一、每条意见先定性

动笔前给每条意见归类。一条意见可以同时属于两类，例如先用现有证据回答一部分，再收缩其余部分。

| 类别 | 判断依据 | 回应里要有什么 |
|---|---|---|
| 现有证据可直接回答 | 材料中已有结果正面回应了这一担忧 | 指出表图和数值，说明它回答到什么程度；原稿没写清的，把这段证据补进正文 |
| 需要解释设计 | 质疑针对的是设计选择，而该选择有理由 | 说明选择及其理由，它处理了什么，没有处理什么；替代设计不可行时给出可核对的原因 |
| 需要新的分析 | 现有材料回答不了，且分析可做 | 已完成的报告结果；未完成的写成计划，写清设定、报告方式和不同结果下结论怎样变 |
| 需要收缩结论 | 证据支撑不了原主张的强度、范围或指标 | 承认，给出修改前后的措辞，说明标题、摘要、结论同步修改 |
| 审稿人误读或前提不成立 | 先核对意见所述事实与原稿、设计和结果 | 礼貌引用位置和证据澄清；有歧义才改措辞，不凭空认错、道歉或撤回已有证据支持的判断 |

现有证据对作者不利时，也应直接回答，不以计划新分析回避。先核对原稿究竟主张了什么，只收缩超出证据的部分。“未达到显著性水平”作为统计描述可以成立；它不证明没有影响，但不能因此反过来判原句错误。需要回应检验精度时，另外说明它尚不能排除什么，不把原稿偷换成更强的主张再反驳。

## 二、每条回应标明状态

每条回应让读者分清当前状态即可，不强制状态标题。以下区分用于起草时判断。

- 已修改正文。只用于确实完成的稿件修改；仅生成建议段落时写拟替换文字，不把起草当作已落稿。
- 已完成检验。给出结果，包括不利的结果。
- 计划补做。用将来时写设定和报告方式，不写结果，不写“结果稳健”“结论不变”。
- 结论已收缩。给出修改前后的措辞。

信首的修改概述不把计划分析列在“已作修改”之下。用户只提供现有结果时，新分析只能作为计划；没有提供其他章节时，已有检验是否存在先待查阅。用户需要可直接使用的正文，就用已有结果写成，不为可省略的指标制造空位；回应确实取决于尚缺结果时，将这一条明确保留为未完成草稿，不预设结果方向。

中文可用的状态表述例如“该结果初稿已算出但未报告，修改稿列于表 X”“这项比较尚未完成，修改稿拟按以下设定补做”“原摘要的表述超出了现有证据，修改为……”。英文对应例如 "This result was computed for the original submission but not reported; it now appears in Table X", "This analysis has not yet been run. We will estimate ... and report ...", "The original claim was broader than the evidence supports. The abstract now reads ...".

## 三、解释设计时说清边界

回应设计质疑时，说明有依据的选择理由，以及与这条质疑直接有关的取舍。“现有条件下已是可行的最好做法”需要具体依据，不能靠固定句式宣布最优。没有证据的理由待作者核实，不自动改写成研究缺陷，也不为无关可能性追加免责声明。

在有利设定下仍然失效，可以说明问题并不只由某种复杂条件导致；它不能自动证明其他设定会更差。同一设定下修正成功也不能证明普遍有效，回应只说到已证明或已检验的范围。

## 四、收缩结论的写法

收缩时给出修改前后的完整句子，并检查标题、摘要、引言的贡献陈述和结论是否同步。收缩之后说明现有证据仍然支持什么，这部分写具体，不写成笼统的“主要结论不变”。

常见的收缩方式有以下几种。

- 指标收缩。原主张的指标没有改善或没有报告，改为实际改善的指标。
- 范围收缩。优势只在某个预算区间、某类样本、某组参数或某些模型下成立，写明区间，并交代其余部分的表现。
- 强度收缩。预测关联不写成因果或机制，相容不写成证实，点估计差异不写成显著。
- 条件补全。把正文已有的参数条件、样本条件带回摘要和结论。
- 对象收缩。证据来自某类样本，建议和推论不延伸到样本以外的对象。

## 五、补充分析怎样排序

候选分析按三点排序。

1. 它针对的担忧对首要结论的威胁有多大。动摇首要结论的排在只影响次要结论的前面。
2. 结果能否改变结论。两种可能的结果都会被解读为支持原结论的分析，没有信息量，不推荐。
3. 成本。用现有数据和代码即可完成的，排在需要新数据的前面。

只推荐前几项，通常不超过三到五项。每一项写明它能区分哪两种解释，以及各种结果下结论如何变化。下面几类分析常常成本低而信息量大。

- 补一个最难打败的简单基准，或者新方法去掉关键组件后的版本。
- 给噪声量级的差异补上不确定性，例如多次重复、区间、适合数据结构的标准误。
- 把在测试集或全样本上做过的选择，改成在此前的数据上冻结后重新评估。
- 对只在一个取值上检验过的主张，补上实际使用中更常见的取值。
- 对解释性的“其原因在于”，用已有的运行记录或分组数据直接检验。
- 中间量的改进之后补端到端的对照，确认它转化为最终结果。

不推荐的做法包括开列很长的“还可以做”清单，建议与首要结论无关的扩展，以及为了显得周全而增加没有针对对象的检验。

## 六、投稿前自查

没有审稿意见时，按下面的顺序做自查，交付时只给结论，不展示过程。

1. 列出标题、摘要、引言贡献和结论中的每一条主张。
2. 逐条找到支撑它的比较和数值。找不到的、强度对不上的、条件被省略的，先标出来。
3. 站在严格审稿人的角度，提出最可能被问到的三到六个问题，优先针对首要结论最薄弱的环节。
4. 每个问题按第一节归类，指出文内已有的回答材料和位置。
5. 按第五节给出最值得补的分析。

## 七、不做的事

不编造没有做过的检验或结果，不隐去关键的不利结果，不把相关写成因果，不把没有解决的问题写成已经排除。不为了让回应显得有力而加入材料没有的数值。文献的作者、年份和卷页不凭记忆写入回应信；建议引用某项方法时点出方法名称，在正文之外提示核实出处。不用大段客套或对审稿人的称赞代替内容。论文正文不是审稿记录，根据论文推想出的质疑与回应须标明为合成示例。
